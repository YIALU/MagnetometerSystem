### 3.2 主窗口
- `MainWindow.xaml`：72 px 导航栏（采集 / 连接 / 命令 / 数据 / 分析 / 扩展·校正 / 设置）+ 顶部「数据链路」条 + 保存失败横幅 + 页面区。原来的底部状态栏和“录制中”卡片已删除。
- 链路条三段计数各有来源，不混用：接收 = `ConnectionVM.ReceivedByteCount`；解析 = `ConnectionVM.ParsedReadingCount`（实测频率 = 每秒新增帧数，`MainViewModel.SampleLinkRates`）；保存 = `SessionListVM.SavedReadingCount` / `PendingReadingCount`。「异常 N」按钮跳到采集页底部的“原始报文”。
- 手动正交度采集进行时，链路条右侧显示“记录当前点”，在任何页面都能记录（替代原来导航栏的蓝色卡片）。
- `MainViewModel`：`CurrentPage`（`AppPage` 枚举）驱动导航；`LinkState` 由 `IsConnecting / IsAcquiring / IsConnected` 推导；`Events` 记录连接、首帧、会话创建与结束、保存失败与恢复（底部“事件”页）。
- 兼容：旧代码或测试把 `CurrentView` 设为 `SessionListViewModel` / `HistoryPlaybackViewModel` / `OrthogonalityCalibrationViewModel` / `SensorCalibrationViewModel` 时，会自动转到合并后的「数据」或「校正」页（`OnCurrentViewChanged`）。

### 3.6 数据页（会话 + 回放）
- `ViewModels/DataPageViewModel.cs` + `Views/DataPageView.xaml(.cs)`：左边会话列表，右边详情（信息、回放入口、按名称勾选导出通道、CSV 选项、生成校正数据）。回放在同页打开，有“返回会话列表”。

### 3.7 分析页（REQ-005 首版）
- Core：`Core/Processing/DriftNoiseAnalyzer.cs`。漂移 = 按实际时间戳最小二乘斜率（单位/小时）+ 分段均值及极差；噪声 = 不重叠时间窗口内去趋势（或去均值）后的标准差，取中位数和最大值；数据质量包括点数、非有限值、实际时长与频率、缺失次数与最长缺失。测试：`DriftNoiseAnalyzerTests`（恒值、已知线性漂移、固定种子白噪声、不均匀与缺失时间戳、数据不足、非法参数）。
- App：`ViewModels/AnalysisViewModel.cs` + `Views/AnalysisView.xaml(.cs)`。只列出已结束且不是旧格式的会话；按会话通道名称和单位选择；时间段用相对秒数；按 30 分钟分块读取，可取消；默认用原始值（`OriginalChannelValues ?? ChannelValues`）；结果可导出 CSV，首行写明时间段和分析设置。只读数据库，不进入任何数据流。

### 4.3 与原型的差距（功能性）
- **原始报文按帧显示解析结果**：原型逐帧标出“校验通过 / 校验失败 / 重新同步跳过 N 字节”，目前只显示收到的原始数据块，加上解析异常总数和最后一条错误。要做到原型的程度，需要扩展 `Core/Protocol/IParserDiagnostics`（例如记录最近 N 条“帧起点、长度、结果、跳过字节数”），在 `ConnectionViewModel.OnDataReceived` 的 `_receiveGate` 内收集，再按现有 `FlushReceiveStatus` 的节流方式送到 UI。不能每个字节都发 UI 事件。
- **收发页**：仍是 `DeviceCommandVM.CommunicationLog` 文本框，原型是带方向徽标的表格。需要先把日志改成结构化记录（时间、方向、字节、结论）。
- **曲线交互**：原型可以在曲线上拖动选区间、有十字准线；目前区间只能输入起止秒数。
- **通道颜色**：默认色仍是 `ChannelDisplayConfig.PresetColors`（旧的高饱和色）。色块面板第一行是校验过的 8 色。要把默认色改成新色板，需要修改测试 `PresetColors_FirstEightUnchanged`，该测试是有意固定旧色的，**先问用户**。

## 5. 需要人工验证的清单

在 Windows 上 `dotnet run --project src/MagnetometerSystem.App/MagnetometerSystem.App.csproj`，逐项确认并记录结果：

1. 串口真实设备：连接 → 链路条三段计数增长、实测频率合理 → 断开 → 会话尾批提交（“事件”中出现“会话已结束，尾批已提交”）、数据页能看到会话且条数一致。

4. 暂停显示、折叠侧栏或停靠区、专注模式、切换页面、显示偏移、滤波都不减少保存条数。
