## 变更记录

### [2026-10-10] v0.6.6 — 视图模型拆分第 5 步：校正采集

- **说明**：拆分的第 5 步，只调整代码结构，界面、原始数据保存和计算结果不变。正交度校正视图模型里的实时拟合采集、原始 CSV 写入、样本存放和拟合通道选择拆成独立的类；视图模型从 1,526 行降到 1,119 行。
- **样本**：拟合样本连同单位、通道数、来源与所选通道放进 Core 的 `CalibrationSampleSet`，整批替换，追加、撤销和清空都带这一批的代号；换了一批之后，旧批次的读数回调、撤销和计算结果都不会混入。
- **实时采集**：订阅读数、按开始时冻结的通道取样本、手动 48 点取最近 10 条读数的均值、链路条状态和实时值移到 `LiveCalibrationCollector`。接收线程只入队，经排队的通知更新界面，从不等待界面线程；新增样本的刷新仍排在输入与渲染之后。
- **原始 CSV**：文件命名、文件头、逐点追加、撤销 / 清空的注释行和失败说明移到 `CalibrationRawCsvRecorder`，文件格式与之前相同。
- **拟合通道**：选项、按名称自动建议、所选通道的检查与提示移到 `FittingChannelSelectorViewModel`；第 2 步的下拉框、“自动识别”和提示的绑定路径改为 `Fitting.*`。
- **细节**：采集中再次执行“开始采集”不再重复订阅读数（界面此时本就隐藏该按钮）；上一次采集排队中的实时值不会再显示到新开始的采集里。
- **测试**：新增 Core 单测 6 个（整批替换、过期代号被忽略、撤销与清空时两组样本对齐、快照独立、边追加边复制）；App 测试新增实时采集 8 个、原始 CSV 5 个、拟合通道 4 个，均不需要打开窗口。

### [2026-10-10] v0.6.5 — 视图模型拆分第 4 步：曲线缓冲与显示偏移

- **说明**：拆分的第 4 步，只调整代码结构，界面、原始数据保存和计算结果不变。实时图表的曲线数据缓冲移到 Core 的 `ChartSampleBuffer`，显示偏移移到 `DisplayOffsetViewModel`；实时图表视图模型从 1,193 行降到 920 行。
- **曲线缓冲**：`ChartSampleBuffer` 保存时间轴、每个通道的显示值和原始值以及通道名称、单位，每通道仍保留 10 万点；读数先于采集开始到达或通道多于协议时补 NaN 并扩展通道、时间从第一条读数起算等规则不变。曲线、统计、区间分析和归零都从它复制数据。
- **显示偏移**：一键归零、取消归零，以及右侧面板单个通道（含计算通道）的“按均值归零”和“清除”移到 `DisplayOffsetViewModel`，计算方式不变；工具栏和右侧面板的绑定路径改为 `Offsets.*`。
- **测试**：新增 `ChartSampleBuffer` 的 Core 单测 7 个（显示值与原始值分开、回绕后的时间窗口、晚到通道补 NaN、重新开始采集后的通道、清空、副本独立、边写边复制时逐行对齐）；App 测试增加单个通道按均值归零与清除、“取消归零”按钮随偏移出现、偏移变化的订阅在移出列表和释放后解除。

### [2026-10-10] v0.6.4 — 视图模型拆分第 3 步：对话框接口与三个子视图模型

- **说明**：拆分的第 3 步，只调整代码结构，界面、原始数据保存和计算结果不变。视图模型不再直接弹出对话框，改为通过 `IDialogService`（正式程序用 `WpfDialogService`，弹出的对话框与之前相同）；配置库、计算通道向导和区间分析拆成独立的子视图模型。正交度校正视图模型减少约 130 行，实时图表减少约 290 行。

- **测试**：配置库的删除确认、删除失败显示原因、JSON / CSV 导出与取消；导入 CSV、选择会话、格式说明经对话框接口；区间导出先问保存位置；绑定错误检查增加展开的总场、梯度向导和有数据的区间统计；区间 CSV 写出的 Infrastructure 单测。

### [2026-10-10] v0.6.2 — 日志补齐连接、解析与保存记录

- **核心错误写进日志文件**：连接收包、协议解析、数据分发、保存失败与重试、数据库初始化等原先用 `Trace` 报告的错误，发布版里只输出到调试器、日志文件里看不到；现在统一转写进 `logs\app-*.log`。同一类消息每分钟最多写 5 条，其余计数后补一行汇总，逐帧错误不会撑满日志。
- **记录采集过程**：开始采集时记下连接方式（串口端口与参数，或 TCP 地址）、协议名、通道名与单位、标称采样率；连接状态变化（含 TCP 重连）；断开时记下收到字节数、接纳帧数和解析错误数；会话创建与结束时记下会话编号、接纳条数和已提交条数；保存失败与重试结果。
- **启动信息**：启动行带上版本号与提交号、安装版/便携版、Windows 与 .NET 版本、日志目录；数据库就绪后记下数据库路径。
- **更新检查**：距上次检查不足 24 小时而跳过联网时也写一行日志（此前这一分支不留痕迹，#15 这类问题无法从日志判断）。
- **日志大小**：单个日志文件超过 10 MB 时当天滚动到新文件，仍最多保留 30 个文件。
- **软件**：采集、保存和界面行为不变，只多写日志。为后续“反馈时附带日志”做准备。

### [2026-10-10] v0.5.9 — 自动检查更新在运行期间也会触发

- **运行期间复查**：自动检查更新原先只在启动时做一次，且距上次检查不满 24 小时就跳过，长期不关的程序永远收不到新版本提示（#15）。现在程序运行期间每小时看一次是否已满 24 小时，到期即静默检查；检查失败不记时间，断网时按这个节奏重试。“稍后提醒”的版本次日会再提示一次，已“跳过此版本”的照旧不提示；同一版本 24 小时内只弹一次（重启后仍算；冷却内只挂角标不弹窗），从“关于”手动检查弹出过的也算（某个平台连不上时会每小时重试，但不再每小时弹窗）；更新窗口已打开时不再叠第二个。
- **当天重启保留角标**：发现的新版本会记下来。重启时状态栏的“有新版本”角标先按上次结果恢复（24 小时内重启不联网；到期联网但失败时也保留），点开直接看更新内容；已跳过、已安装到该版本或之后确认已是最新时不再恢复；运行中再次检查确认已是最新（例如发布被撤回）时，角标随之撤下。切换更新平台后，以前记下的版本和检查时间作废，角标撤下，下一轮按新平台重新检查；切换会等进行中的检查结束后再清除。定时检查、手动检查和切换平台互斥进行，较早的结果不会在较新的结果之后再弹窗，切换完成后新平台的结果也不会被清掉。
- **时钟回拨**：上次检查时间落在当前时间之后（系统时钟被往回调过）时按到期处理，不再长期停止检查。

### [2026-10-07] v0.5.4 — 校验开关与采集、分析、校正改进

- **校验开关**：二进制协议的校验段新增“启用校验”。帧里预留了校验字段但固件尚未计算时关闭，这些字节照常占位、不比对，参数保留，固件启用后勾选即可；解析记录注明“校验未启用”。没有该字段的旧协议保持原来的校验行为。
- **数采卡协议**：“磁梯度数采卡-pt”两个内置协议的 CRC 字段固件未启用，校验段按文档预置但默认不校验，选上即可连接（原先因 CRC 待确认被禁止采集）；以前保存的副本加载时自动换成同样的未启用校验段。CCT-5 的 CRC 校验保持启用。
- **采集页**：图表工具栏新增“一键归零”，把当前显示的各曲线按时间窗口内的均值移到 0（暂停时按冻结画面），只改显示偏移，不影响保存的原始数据和统计；有偏移时显示“取消归零”。
- **分析页**：选择的通道较多时，结果表在表内滚动，最多占右侧 55%，曲线保留其余空间（原先超过约 4 个通道就显示不全且无法滚动）。
- **校正页**：正交度拟合的“采集数据”不再要求连接恰好 3 / 6 个通道，新增“拟合通道”选择，按名称自动识别各探头的 X / Y / Z（如数采卡的 X1…Z2、CCT-5 交错排列的通道），可手动更改；实时采集、手动 48 点和已保存会话都按所选通道取值。
- **会话名称**：新会话默认命名为“协议名 + 开始时间”，导出文件的默认名称沿用会话名（改过名的补上开始时间）。
- **版本显示**：窗口标题和版本提示只显示版本号，提交号保留在“关于”窗口。
- **开发工具**：新增 `tools/serial_simulator/` 串口数据模拟器（Python 窗口程序），按协议配置生成帧并可注入噪声、坏校验、截断、粘包和分包，用于手动联调。

- **单位与改正保护**：正交度配置记录拟合单位，应用时严格匹配；旧配置未记录单位时保持未知，拒绝直接应用。拟合输入、异步结果和参数快照保持单位关联。改正版本包含两组配置、通道映射、单位和参数指纹，不覆盖其他版本；CSV 记录完整 `CorrectionVersion`，旧单配置 ID 结果仍可读取。
- **通信与升级诊断**：明确区分本地写出、匹配响应与设备执行。设备内部存储下载尚无隔离接收流程，ZDZ“读取存储数据”预设暂禁发送；ZDZ 预设须先确认 CRC 参数。更新包按完整版本文件名选择，必须有有效 SHA256 才能下载或复用缓存。

- **串口退出保护**：读取字节后释放 I/O 锁再通知订阅者，避免采集回调同步等待 UI、UI 断开连接等待同一把锁时死锁。

- **命令顺序**：发送操作保持串行直到响应、超时或断连取消，避免后条覆盖前条等待；断连或释放后不写出旧排队命令。无请求 ID 协议的超时后迟到 ACK 仍有归属歧义。

- **拟合范围保护**：正交度实时/会话拟合仅接受明确的三轴或双三轴完整数据源；含温度、额外通道或元数据不完整时拒绝截取前缀。任意拟合通道映射尚未实现，可整理明确三轴 CSV 后导入；此限制不影响普通采集和已有显式映射改正。

### [2026-03-21] 二进制协议配置重构：帧段式(FrameSegment)替代字节偏移(ByteOffset)

- **变更**: 新增帧段式(FrameSegment)协议配置模式，替代原有的 FieldMapping + ByteOffset 模型。用户从上往下逐段配置帧格式（帧头→长度→数据字段→校验→帧尾），系统自动计算偏移和总帧长。
- **原因**: 原有 ByteOffset 方式要求用户手动计算每个字段的偏移量，不直观且容易出错。帧段式"搭积木"方式更符合用户直觉。
- **影响范围**:
  - 新增: `FrameSegment.cs`（帧段模型，含 SegmentType 枚举、ChecksumAlgorithm 枚举）
  - 修改: `ProtocolConfig.cs`（新增 Segments 列表、UsesSegments 属性、ComputeSegmentOffsets/MigrateFromLegacy 方法、段式预设工厂）
  - 修改: `ConfigurableBinaryParser.cs`（新增段式解析路径，兼容旧 FieldMapping 模式）
  - 修改: `ConnectionViewModel.cs`（新增 ProtocolSegments 集合及增删移动命令）
  - 修改: `ConnectionView.xaml`（Binary 模式 UI 替换为帧段列表编辑器，ASCII 模式不变）
- **兼容性**: 旧版 JSON 配置文件通过 MigrateFromLegacy() 自动迁移为段式格式
- **计划文档已更新**: 是
