## 变更记录

### [2026-10-07] v0.5.3 — 界面重设计

- **导航与链路条**：改为 采集 / 连接 / 命令 / 数据 / 分析 / 校正 / 设置 七页；深色导航栏与链路条在任何页面显示 接收 → 解析 → 保存 三段计数、实测频率与故障状态。
- **通信诊断**：原始报文逐帧列出解析结论，被拒绝的帧写明原因（如校验计算值与帧内值），重新同步丢弃的字节单独列出；连接页「解析测试」不连接设备即可用当前协议试解析；收发记录逐行写明方向、字节数、应答判定与耗时。
- **采集页**：曲线 + 右侧通道 / 统计 / 区间 / 滤波 / 校正面板 + 底部收发 / 原始报文 / 事件；在曲线上拖动选区间、悬停查看原始值；通道默认色改为 8 色。
- **数据页**：会话列表与回放合并，按通道勾选导出 CSV，导出校正值时选择改正版本；刷新列表或开始、结束采集后保留选中的会话。
- **分析页（REQ-005 首版）**：对已保存会话按通道和时间段计算噪声、漂移与数据质量，可导出结果。
- **校正页**：正交度四步向导（实时连续 / 手动 48 点、导入文件、已保存会话）、配置库、偏移 / 增益按通道表格；拟合继续执行单位规则。
- **修复**：连续正交度采集在接收锁内同步等待界面线程，可能卡住采集；数据页回放层在列表模式下盖住会话详情；通道最新值单位重复显示。
- **验证边界**：Windows 自动回归 718 通过、3 跳过（两个串口测试未设端口变量、一个可选性能测试）；本机虚拟串口 COM1↔COM2 业务链路通过，模拟“磁梯度数采卡-pt (仅磁场6通道)”帧，CRC 参数为测试假设。未手动逐项操作界面，未做实体串口与真实设备验收；数采卡 CRC 仍待固件确认，内置预设默认禁止采集。

### [2026-10-04] v0.5.0 — 通用采集工作台与保存可靠性

- **通用协议与连接**：通道数量、名称、单位由协议配置，不再按设备类型限制；标称采样率只记录元数据，不隐式改变设备输出。加强 ASCII/二进制分包、粘包、校验及坏帧重新同步，区分 CTMBS 实时测量、状态与时钟等命令响应。
- **可靠保存**：打开连接前准备会话，原始读数由关键保存消费者接纳后才计数和绘图；可选处理不能覆盖原始值。保存失败立即停收，已接纳数据保留待显式重试；断开、退出和安装更新前等待尾批保存，失败不宣称完成。恢复成功后可再次连接。
- **曲线优先的工作台**：连接、收发、通道及分析面板可折叠，专注模式退出后恢复开合状态；单图共用绘图区，温度等异单位通道使用独立轴。保留多图单列/双列、通道配置、统计、区间分析、滤波及计算通道；暂停显示和折叠不减少原始保存。
- **历史与导出**：按记录时间戳回放，支持暂停、定位和倍速；隔离历史显示与实时保存。通道名称、单位和索引随会话保存；支持选择原始、改正或并列数据导出，以及时间、通道和精度选项。
- **单位与改正保护**：正交度配置记录拟合单位，应用时严格匹配；旧配置未记录单位时保持未知，拒绝直接应用。拟合输入、异步结果和参数快照保持单位关联。改正版本包含两组配置、通道映射、单位和参数指纹，不覆盖其他版本；CSV 记录完整 `CorrectionVersion`，旧单配置 ID 结果仍可读取。
- **通信与升级诊断**：明确区分本地写出、匹配响应与设备执行。设备内部存储下载尚无隔离接收流程，ZDZ“读取存储数据”预设暂禁发送；ZDZ 预设须先确认 CRC 参数。更新包按完整版本文件名选择，必须有有效 SHA256 才能下载或复用缓存。
- **刷新内存开销**：实时刷新直接复制显示与统计需要的时间范围，避免每帧复制全部保留历史；暂停保留一次完整快照，扩窗和隐藏来源计算保持可用。完整原始数据保存不受影响。
- **串口退出保护**：读取字节后释放 I/O 锁再通知订阅者，避免采集回调同步等待 UI、UI 断开连接等待同一把锁时死锁。
- **响应诊断**：CTMBS 未知简单响应计入解析错误并重新同步，合法 ACK、ERR 及启停标识保持兼容。
- **命令顺序**：发送操作保持串行直到响应、超时或断连取消，避免后条覆盖前条等待；断连或释放后不写出旧排队命令。无请求 ID 协议的超时后迟到 ACK 仍有归属歧义。
- **通道身份保护**：CTMBS 按 3125/3124/3123/3129 通道码映射到 D/H/Z/T，拒绝未知或重复码，避免设备调整字段顺序后错配名值。
- **拟合范围保护**：正交度实时/会话拟合仅接受明确的三轴或双三轴完整数据源；含温度、额外通道或元数据不完整时拒绝截取前缀。任意拟合通道映射尚未实现，可整理明确三轴 CSV 后导入；此限制不影响普通采集和已有显式映射改正。
- **验证证据**：2026-10-04 本机 Windows 自动回归为 **616 通过、1 跳过、0 失败**；包括真实临时 SQLite/CSV、本机 TCP 收发及 WPF 业务生命周期测试。跳过项为缺少串口环境的串口回环测试；**未完成实体设备、USB/串口驱动和现场通信验收**。最终发布提交仍须核对最新 CI、审查和产物验证，详见 [测试与验收](testing-and-acceptance.md)。
- **数据与发布边界**：旧固定列数据表保留并提示迁移，尚未自动转换供回放；内存待写批次不是断电恢复日志。0.5.0 发布目标为 GitHub Releases；应用自动更新源仍为 Gitee，仅发布 GitHub 不会向现有用户推送更新。Gitee 同步须另获授权。

### [2026-03-21] 二进制协议配置重构：帧段式(FrameSegment)替代字节偏移(ByteOffset)

- **变更**: 新增帧段式(FrameSegment)协议配置模式，替代原有的 FieldMapping + ByteOffset 模型。用户从上往下逐段配置帧格式（帧头→长度→数据字段→校验→帧尾），系统自动计算偏移和总帧长。
- **原因**: 原有 ByteOffset 方式要求用户手动计算每个字段的偏移量，不直观且容易出错。帧段式"搭积木"方式更符合用户直觉。
- **影响范围**:
  - 新增: `FrameSegment.cs`（帧段模型，含 SegmentType 枚举、ChecksumAlgorithm 枚举）
  - 修改: `ProtocolConfig.cs`（新增 Segments 列表、UsesSegments 属性、ComputeSegmentOffsets/MigrateFromLegacy 方法、段式预设工厂）
  - 修改: `ConfigurableBinaryParser.cs`（新增段式解析路径，兼容旧 FieldMapping 模式）
  - 修改: `ConnectionViewModel.cs`（新增 ProtocolSegments 集合及增删移动命令）
  - 修改: `ConnectionView.xaml`（Binary 模式 UI 替换为帧段列表编辑器，ASCII 模式不变）
- **兼容性**: 旧版 JSON 配置文件通过 MigrateFromLegacy() 自动迁移为段式格式
- **计划文档已更新**: 是

### [2026-03-21] 帧段 ByteCount 可编辑 + 采样率说明

- **变更**:
  1. 帧段的 ByteCount 字段在 UI 上按类型区分：Header/Tail/LengthField/Checksum/Padding 类型可手动编辑（支持帧头 2/4/5 字节、帧尾 1/2 字节等灵活配置）；DataField 类型由 DataType 自动计算（Float=4, Double=8, Int16=2 等），不可手动修改
  2. FrameSegment 实现 INotifyPropertyChanged，DataType 变更时联动更新 ByteCount
  3. 采样率(SampleRate)保留，补充注释说明当前仅用于 UI 显示和会话元数据记录，降采样/插值(SamplingRateAdapter)尚未实现
- **原因**: 用户要求帧头帧尾长度可调（如帧头 4-5 字节），数据字段字节数应随数据类型自动变化
- **影响范围**:
  - 修改: `FrameSegment.cs`（实现 INotifyPropertyChanged，ByteCount/DataType 属性联动）
  - 修改: `ConnectionView.xaml`（字节列条件可编辑）
  - 修改: `ConnectionViewModel.cs`（监听段 PropertyChanged 同步帧长）
  - 修改: `SensorConfig.cs`（SampleRate 注释补充）
- **计划文档已更新**: 是
