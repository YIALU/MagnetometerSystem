# 匿名需求与问题反馈方案

状态：简化表单、草稿恢复、匿名接收服务及后台 GitHub 建单已实现并部署。维护者已配置服务器授权，2026-10-05 通过真实桌面调用链生成 [联调 Issue #5](https://github.com/YIALU/MagnetometerSystem/issues/5)，验证隐私、重复提交及服务重启后去重，测试单已关闭。维护与授权步骤见 [部署说明](../feedback-deployment.md)。

## 两项必填，两项选填

从主窗口状态栏「反馈与建议」或「关于 → 反馈与建议」打开一个小对话框，不占用实时曲线工作台。使用场景、问题或需求描述必填；姓名、联系方式选填，不填写也能提交。不要求标题、分类或登录。

```text
反馈与建议

使用场景
┌─────────────────────────────────────────────────┐
│ 你在做什么？例如：串口采集后导出某个时间段的数据。│
└─────────────────────────────────────────────────┘

问题或需求描述
┌─────────────────────────────────────────────────┐
│ 遇到了什么问题，或希望增加什么功能？              │
│ 可以说明实际结果，以及希望达到的效果。            │
│                                                 │
└─────────────────────────────────────────────────┘

姓名（选填）       [                            ]
联系方式（选填）   [邮箱、电话或其他联系方式      ]

自动附上软件版本。场景与描述将公开到项目 GitHub。
姓名和联系方式仅供项目维护者查看，不公开到 GitHub。
无需登录，提交后由项目维护者审核。

                              [取消] [提交反馈]
```

不再设置列表侧栏、模块选择、影响等级、独立标题、状态筛选或额外预览步骤。场景和描述原文组成公开正文，公开提示直接放在提交按钮上方；姓名和联系方式单独保存，不进入公开正文。联系方式允许自由填写邮箱、电话或其他方式，不限制为某一种格式。软件版本自动附上；不自动上传日志、设备地址、协议、原始数据、截图或任何密钥。

提交成功显示「反馈已收到，编号……」，已经同步 GitHub 时提供「查看反馈」链接。失败显示原因并保留填写内容，允许重试。编辑内容自动保存为本地草稿，重启后恢复；不向用户暴露队列和同步管理页面。关闭对话框不影响采集、保存或绘图。

## 用户匿名提交，维护者决定处理

流程：**填写场景和描述（可选留下姓名、联系方式） → 服务器接收并保存 → 服务创建 GitHub 待审核 Issue → 维护者决定是否改进。**

软件提交使用场景、描述、版本、随机 FeedbackId，以及用户主动填写的可选姓名和联系方式。服务根据描述生成简短 Issue 标题，正文保留场景和描述原文，不强制用户先判定 Bug 或需求。姓名和联系方式不进入标题、Issue 正文、标签、公开查询响应或普通请求日志，只在服务器私有存储中保留；维护者通过受保护的管理访问或 SSH 查询，不为软件用户增加管理入口。

新建 Issue 标记 `feedback`、`needs-triage`。维护者在 GitHub 中决定采纳、修复、不采纳或关联重复问题；提交成功不代表已承诺改进，关闭 Issue 不自动等同于修复。首版不增加用户账号、邮箱通知、评论或复杂状态中心。

GitHub 创建 Issue 需要授权身份，但这由服务器处理，软件用户无需注册或登录。[创建 Issue API](https://docs.github.com/en/rest/issues/issues#create-an-issue)

## 使用已有公网服务器

用户已提供公网服务器 IP 和仓库根目录下的 SSH `.pem` 密钥。已通过 root / 22 成功登录并部署独立接收服务、独立 HTTPS 代理及续期任务，保留原有 Caddy 服务。当前没有域名，使用可信 IP 地址证书。公开反馈 URL 随软件构建发布；SSH 密钥和私人部署配置不写进软件源码。

SSH 私钥只用于本机连接服务器，不复制到程序、发布包、服务器应用目录或代码仓库。根工作区及独立开发工作区均加入 `*.pem` 忽略规则；文件未被 Git 跟踪，不打印密钥正文。Windows SSH 曾因原文件权限过宽拒绝读取；本次使用仅当前用户可访问的本地临时副本连接，结束后已删除副本，原密钥文件和权限未改动。

无域名的 HTTPS 使用可信 IP 地址证书，有效期约六天，已配置每天两次检查续期，并通过测试 CA 续期及代理加载钩子的演练。公网验证路径可达，Windows HttpClient 的默认证书校验通过；没有跳过证书验证。[官方 IP 证书说明](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)

SSH 密钥不等于 GitHub 写入凭据。当前实现使用维护者配置的细粒度令牌，仅授予本仓库 Issues write；GitHub App 自动换取安装令牌暂未实现。软件中不包含写入凭据。[安装身份认证](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/authenticating-as-a-github-app-installation)

接收服务独立目录、独立进程及持久化存储，不影响服务器已有业务；先检查现有服务和反向代理，再确定端口与部署方式。接收端只允许写入 `YIALU/MagnetometerSystem`，限制正文大小和提交频率，正常用户不需要账户。

## 隐藏在后台的可靠性

- 本地独立保存草稿，不与采集数据库共用写事务；失败不会清空内容或停止保存。
- 服务先持久保存反馈和待同步任务，才返回回执；服务器重启后继续同步。
- 相同 FeedbackId 重试返回原记录，重复点击不重复创建 Issue。
- GitHub 创建超时且结果未知时，按正文中的 FeedbackId 核对；无法确认时留待人工核对，不盲目重发。
- 服务已接收但 GitHub 暂时不可用时，用户仍看到真实回执；不误报已经创建 Issue。
- 用户端只能读取公开反馈，不暴露服务端凭据、私有管理接口或部署信息。

## 验收

验收重点是未登录用户可以完成两项必填内容并提交；姓名和联系方式为空仍能提交，填写时维护者能够查看而公开 Issue、查询和日志不包含这些字段；中文和长正文不丢失；断网、重启、重复点击、丢失响应及服务器重启不会丢反馈或重复建单；GitHub 401/403、限流时仍保留已接收记录；界面不会显示未经证实的成功。

在采集期间填写与提交，原始保存和实时绘图应继续正常运行。正式仓库联网建单验证需要维护者授权，使用明确标注的单条测试反馈并在完成后关闭，不批量建单。本次真实建单验证未同时连接实际串口设备。

本方案替代旧 `docs/superpowers/specs/2026-08-27-in-app-feedback-design.md` 中的桌面端内嵌令牌方案，不按旧文档实现客户端凭据。
