### 2026-10-06：关闭事件重入补修

用户提供的截图显示旧标题“数据尚未保存”和旧异常拼接文案，同时暴露了此前测试遗漏的关闭分支：保存操作立即完成时，直接在 WPF `Closing` 事件内再次调用 `Close()`，会触发“在窗口关闭期间……无法调用 Close”的异常。这条异常不证明数据未写入。

已将成功保存后的关闭调用排入 Dispatcher，等待原关闭事件返回后再执行；主目录与独立工作区均做此最小修复，并各新增 `ImmediatelyCompletedSaveClosesAfterOriginalClosingEventReturns` 回归测试。没有覆盖主目录已有改动，也没有把其他新文案整套复制到主目录。

针对本次修改重新构建并运行 `ShutdownUpdateTests`：独立工作区 6/6 通过，主目录 4/4 通过，均为 0 失败。新增用例确认立即完成保存时，第一次关闭取消、稍后第二次关闭成功，没有重入；原异步等待及失败恢复用例保持通过。对应 TRX 分别保存在独立工作区 `artifacts/req-01-04/close-fix-test-results/` 与主目录 `.codex_tmp/close-fix-test-results/`。上面的 665 项全套回归是补修前的历史证据，此处记录补修当时的定向验证；收尾完整回归结果见下方。

### REQ-001：关闭提示使用面向用户的表达

**评估**：采纳，P1。关闭涉及数据保存，提示应让用户知道当前数据状态和下一步。issue 未提供弹窗截图或全文，尚不能确定反馈指的是正常关闭、保存失败还是其他窗口关闭。

**源码依据**：[反馈版本 MainWindow.xaml.cs](https://github.com/YIALU/MagnetometerSystem/blob/986b482/src/MagnetometerSystem.App/MainWindow.xaml.cs) 的 `OnClosing` 在失败时直接拼接 `ex.Message`；本地同一方法也有此行为。技术异常可能进入用户提示，但不能据此认定这就是反馈所指弹窗。

**下一步与范围**：复现并盘点关闭相关提示，按“正在保存 / 已保存可退出 / 保存失败暂不能退出”组织文案；失败给出可操作的处理方法，完整异常保留在日志或可展开详情中。保留尾批保存等待和失败后阻止退出的行为。

**验收**：正常关闭、采集中关闭、保存失败三个场景分别检查；用户可以从提示理解是否已保存及如何处理，默认不展示堆栈或内部对象名；保存成功前不退出，失败后可以继续处理并重试。
