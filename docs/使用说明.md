# 使用说明

[返回项目介绍](../README.md) · [English](user-guide.en.md)

## 连接与协议配置

选择串口或 TCP，并填写连接参数。设备需要启动采样命令时，连接后从命令面板发送对应命令。

协议决定数据的解析方式及通道含义。ASCII 协议需要配置行尾、分隔符和字段映射；二进制协议需要配置帧结构、数据类型、字节序、缩放与校验。确认通道顺序、名称和单位与设备输出一致后，可以将配置保存或导出为 JSON。

“磁梯度数采卡-pt”的两个内置预设（ZDZ_C08）帧中有 CRC 字段，但固件尚未启用计算，校验段默认不启用，选择后即可连接；固件启用 CRC 后，在校验段勾选“启用校验”。校验配置、旧协议 JSON、可变长度段与各预设的单位说明见[协议校验与通道单位](协议校验与单位.md)。

标称采样率记录在会话中，不会自动下发命令，也不表示设备确认的实际输出频率。图表刷新率控制界面更新。历史回放根据读数时间戳和倍速播放。

## 保存、回放与导出

连接前准备采集会话，有效读数自动保存。这里的“原始读数”是协议解析后、校正前的通道值，包含协议规定的缩放或单位转换。原始字节窗口用于通信调试；数据库保存的是读数，并非完整线缆字节流。

暂停显示、折叠面板、显示滤波与降采样不减少原始保存。图表每通道保留最近 100,000 点用于显示和区间分析，完整会话数据以 SQLite 中已提交的记录为准。

保存失败时停止接收新测量并断开，已接纳的待写批次保留在进程内。修复原因后点击“重试保存”，完成旧会话后再重新连接。待写队列不是持久化恢复日志，断电或强制结束进程可能丢失尚未提交的数据。正常断开和关闭应用时等待保存完成。

在数据管理中选择会话进行查询、回放或 CSV 导出。回放支持暂停、定位和倍速，实时连接期间禁用回放。导出可以选择时间范围、通道、精度，以及原始值或已保存的改正结果。

设备内部存储下载尚无独立接收流程。ZDZ 的“读取存储数据”预设暂不可发送；普通自定义命令或自由 HEX 也不具备下载隔离能力。本机已保存会话的 CSV 导出正常可用，详见[设备存储下载边界](协议校验与单位.md#设备存储下载边界)。

## 设备命令与响应

选择协议关联的命令组，填写参数后发送，或使用 ASCII/HEX 自由发送。检查设备所需的行尾、字节序与校验。

界面的“已写出”表示当前连接完成了本地写出；“收到匹配响应”表示收到符合判据的报文；设备是否执行成功仍需根据协议含义或实际行为判断。发送操作串行等待响应、超时或断连取消。未设置响应判据的自由发送等待至超时或取消，无请求 ID 的协议仍可能存在超时后迟到 ACK 的归属歧义。

## 数据改正

正交度和偏移/增益工具按需使用，默认采集不依赖校正参数。应用改正时保留原始值，历史批量改正可以另行保存结果。

正交度参数的拟合单位必须与应用通道一致；`uT`、`µT`、`μT` 视为同一单位，不自动换算偏移参数。旧参数未记录单位时保持未知，需要重新拟合或导入明确单位的参数。

实时采集、手动 48 点和已保存会话的拟合样本，按向导第 2 步“拟合通道”所选的通道取值：单三轴为 X/Y/Z 各选一个通道，双三轴为两组探头各选一组。程序按通道名称自动识别（如 X1/Y1/Z1、Bx/By/Bz），可手动更改；温度、梯度等其余通道不参与拟合。所选通道必须互不重复，且使用同一明确磁场单位（nT/uT/mT/T）。从文件导入时使用三列（双三轴为六列）的 CSV / TXT，并选择数值单位。普通采集、绘图和已有显式通道映射的改正不受拟合通道选择影响。

实时采集开始后，第 2 步采集区下方显示“原始数据文件”的文件名、保存目录（默认 `%LocalAppData%\MagnetometerSystem\statistics\calibration_raw`）和已写入的行数，可点“打开文件”或“打开所在文件夹”。文件逐点追加，手动模式的撤销 / 清空只追加 `#` 注释行；停止采集后仍显示最近一次的文件。文件无法创建或写入失败时，这里显示原因，采集照常进行，拟合样本不受影响。

历史批量改正按版本保存结果。版本标识包含两组配置 ID、通道映射、拟合单位和计算参数指纹，同一配置 ID 修改参数后保留旧结果。导出时从“已保存改正版本”选择，CSV 的 `CorrectionVersion` 列记录完整标识。旧单配置 ID 的结果仍可选择和导出。

## 数据位置与升级

- 默认数据库：`%LOCALAPPDATA%\MagnetometerSystem\magnetometer.db`。
- 日志：程序目录的 `logs`；目录不可写时回退到 `%LOCALAPPDATA%\MagnetometerSystem\logs`。
- 升级或迁移前关闭程序并备份数据库。旧固定列数据保留在 `readings_legacy_*` / `corrected_readings_legacy_*` 中，对应会话提示迁移；当前不会自动转换这些旧记录供回放或导出。
- 当前开发版支持 GitHub / Gitee 双平台更新，在「系统设置 → 软件更新」选择自动、Gitee 或 GitHub，即时保存。自动模式比较两边正式版本；同版本优先提供完整发布包的平台，两边均完整时优先 Gitee。网络下载失败可切换同版本、同安装方式的镜像，并重新读取其校验清单；校验值缺失、校验失败或用户取消时不自动切换。
- 更新窗口显示下载平台；检测到同版本的两份发布时可手动选择平台。更新包和 SHA256 清单始终来自同一份发布，不拼接下载、不降级到另一平台的旧包。
- 已发布的 V0.5.0 只使用 Gitee 检查更新。两边发布包也可以手动下载，打包与发布过程见[发布流程](发布流程.md)。

## 常见问题

| 现象 | 检查内容 |
| --- | --- |
| 已连接但没有数据 | 设备是否主动输出、连接参数、是否需要启动采样命令 |
| 有原始字节但无有效读数 | 行尾与分隔符、帧长、字节序、校验范围、字段映射 |
| 曲线通道或数值不对 | 通道索引、单位、缩放、显示偏移及计算通道来源 |
| 曲线在动但保存异常 | 保存错误、待写状态、数据库目录权限；绘图不代表事务已提交 |
| 命令已写出但设备没有变化 | 对端接收字节、行尾与校验、响应判据、设备执行条件 |

报告问题时提供程序版本、复现步骤、连接参数、协议 JSON、最小收发报文及相关日志。测试覆盖与实际设备验收记录见[测试与验收](testing-and-acceptance.md)。

## 反馈与建议（开发版）

从主窗口状态栏或关于窗口打开「反馈与建议」，填写使用场景及问题或需求描述。姓名和联系方式选填，不需要注册或登录。场景、描述和软件版本用于公开 Issue；姓名和联系方式仅供维护者查看。窗口不会禁用主窗口，编辑内容自动保存草稿，提交失败可按原编号重试。

匿名接收服务已部署，GitHub 自动建单已授权并通过真实链路验证；提交后由维护者决定是否采纳。已发布的 V0.5.0 不包含此窗口，维护步骤见 [反馈服务说明](feedback-deployment.md)。
