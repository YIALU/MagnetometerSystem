# 发布流程

从改完代码到用户能收到更新推送，一共 6 步。版本号唯一的真实来源是 **git 标签**，其他地方都必须跟它对齐。

---

## 前置条件（只需配置一次）

| 项 | 要求 | 检查方式 |
|---|---|---|
| .NET SDK | 8.0 或更高 | `dotnet --version` |
| Inno Setup | **6.4 或更高** | `ISCC.exe /?`；缺失时装：`winget install --id JRSoftware.InnoSetup -e` |
| git | 能跑 `git describe` | `git describe --tags` |

Inno Setup 必须 6.4+：脚本引用了编译器自带的 `compiler:Languages\ChineseSimplified.isl`，
更早的版本没有这个官方简体中文包。仓库里**不**内置 `.isl` 文件 —— 内置的新文件配上旧编译器
会报 "unknown message name"。

---

## 第 1 步：确定版本号

看当前离上一个标签有多远：

```bash
git describe --tags        # 例如 v0.3.2-8-g034f324，说明比 v0.3.2 多了 8 个提交
```

按语义化版本决定新号：

- **修 bug** → 补丁位 +1（0.3.2 → 0.3.3）
- **加功能、向后兼容** → 次版本位 +1，补丁位归零（0.3.2 → 0.4.0）
- **破坏性改动** → 主版本位 +1

版本号必须是**严格三段** `主.次.补丁`。`v1.2`、`v1.2.3.4`、`v1.2.3-beta`
都会被打包脚本和更新服务一起拒绝。

## 第 2 步：同步 `Directory.Build.props`

把 `<Version>` 改成新版本号（**不带** `v` 前缀）：

```xml
<Version>0.4.0</Version>
```

`build.ps1` 会拿它和 git 标签交叉核对，对不上直接中止 —— 防止装出来的程序自报的版本
和标签不一致。（临时验证可以用 `-SkipVersionCheck` 跳过，正式发布不要用。）

顺手更新 `docs/变更日志.md`。

## 第 3 步：提交并打标签

工作区必须**完全干净**才能打包。`build.ps1` 会跑 `git status --porcelain`，
只要有任何输出就拒绝构建 —— 这和 `InjectGitSha` 用的是同一个判据，所以正式发布的产物
永远不会带 `-dirty` 后缀。

```bash
git add -A
git commit -m "chore: 发布 v0.4.0"
git tag v0.4.0            # 标签名带 v 前缀
```

标签必须**正好打在 HEAD 上**。脚本用的是 `git describe --tags --exact-match HEAD`，
HEAD 之后又多了提交就会失败。

## 第 4 步：打包

```powershell
.\build.ps1 -Mode All
```

产物落在 `artifacts/v0.4.0/`：

| 文件 | 说明 |
|---|---|
| `MagnetometerSystem-v0.4.0-portable-win-x64.zip` | 便携版，单文件 exe，解压即用 |
| `MagnetometerSystem-v0.4.0-setup.exe` | 安装版，Inno Setup 安装包 |
| `SHA256SUMS.txt` | 两个包的 SHA256，应用内下载后会拿它校验 |

其他模式：`-Mode Portable` 只出便携版（不需要 Inno Setup），`-Mode Installer` 只出安装版。

`artifacts/` 已在 `.gitignore` 里，不会被提交。

### 两种形态的差别

|  | 便携版 | 安装版 |
|---|---|---|
| 发布方式 | 单文件 exe | 展开目录 + 安装器 |
| 安装位置 | 用户自选 | `%LOCALAPPDATA%\Programs\MagnetometerSystem` |
| 需要管理员权限 | 否 | 否（`PrivilegesRequired=lowest`） |
| 识别标记 | 目录里有 `portable.marker` | 无此文件 |
| 自动更新行为 | 下载后打开所在目录，用户手动解压覆盖 | 静默调起安装器，自动重启应用 |

程序靠 `portable.marker` 是否存在判断自己属于哪种形态（见 `AppVersion.PackageKind`），
进而决定去 release 里下载哪个资源，以及更新时怎么应用。

## 第 5 步：推送并创建 Gitee Release

```bash
git push origin main
git push origin v0.4.0
```

到 https://gitee.com/yialu/MagnetometerSystem/releases 新建发行版：

- **标签**：选择刚推上去的 `v0.4.0`
- **标题**：`v0.4.0`
- **说明**：从 `docs/变更日志.md` 里摘 —— 这段文字会原样显示在用户的更新提示窗口里
- **附件**：把 `artifacts/v0.4.0/` 下的**三个文件全部**上传

> 资源文件名不能改。更新服务靠后缀名匹配：安装版认 `-setup.exe` 结尾，
> 便携版认含 `-portable-` 且以 `.zip` 结尾。改了名字用户就只能看到"打开下载页面"，
> 应用内下载会失效（不会崩，只是降级）。

**预发布**：勾了"预发布"的 release 不会推送给普通用户，可以放心用来内部验证。

## 第 6 步：验证更新链路

发布完之后实际验证一次，别只看接口返回：

1. 装一个**旧版本**（或临时把 `Directory.Build.props` 的 `<Version>` 调低后本地跑）
2. 打开「关于」窗口 → 点「检查更新」→ 应当报出新版本、显示发行说明
3. 点「立即更新」→ 观察下载进度、SHA256 校验通过、安装器自动拉起
4. 安装完成后应用自动重启，「关于」里的版本号变成新版本

也可以直接确认接口本身：

```bash
curl -s https://gitee.com/api/v5/repos/yialu/MagnetometerSystem/releases/latest | head -40
```

仓库是公开的，接口匿名可访问，代码里没有也不需要任何 token。

## 更新机制说明

**检查时机**

- 启动后延迟 8 秒静默检查一次（避开数据库初始化和串口连接的高峰）
- 两次静默检查最少间隔 24 小时
- 网络失败**不**记录检查时间戳 —— 否则出门断网一次就会被压制一整天
- 用户在「系统设置 → 软件更新」里可以关掉自动检查
- 「关于」窗口的「检查更新」按钮不受 24 小时限制，随时可查

**用户可以跳过某个版本**，跳过后该版本不再弹窗，但更新之后的版本仍会提示。

**下载与校验**

下载到 `%LOCALAPPDATA%\MagnetometerSystem\updates`，先写 `.part` 临时文件，
校验 SHA256 通过后才改名为正式文件。任何一步失败都会删掉 `.part`，不会留下
半截文件被误当成下载完成。已下载且校验通过的文件会直接复用，不重复下载。
超过 7 天的旧下载会在启动时自动清理。

**失败时的兜底**：下载或校验失败，更新窗口会把按钮变成「重试」并显示
「打开下载页面」，用户可以手动去 Gitee 下载。

**数据安全**：SQLite 数据库存在 `%LOCALAPPDATA%\MagnetometerSystem` 下，
在程序目录之外，覆盖安装不会碰到它。卸载时会**询问**是否删除数据，默认为否。

## 常见问题

**`build.ps1` 报"工作区有未提交的修改"**
`git status` 看一下。要么提交，要么加进 `.gitignore`。确实需要跳过时用 `-AllowDirty`，
但这样产出的包会带 `-dirty` 标记，不能作为正式发布。

**`build.ps1` 报找不到 ISCC.exe**
装 Inno Setup 6.4+，或者只打便携版：`.\build.ps1 -Mode Portable`。
脚本会在开始编译**之前**就检查它，不会让你白等一次完整的 publish。

**`build.ps1` 报"HEAD 上没有标签"**
标签必须正好打在当前 HEAD。补打：`git tag v0.4.0`。

**版本号交叉核对失败**
`Directory.Build.props` 的 `<Version>` 和 git 标签对不上，按第 2 步改掉。

**用户收不到更新提示**
按顺序排查：release 是不是勾了「预发布」；tag_name 是不是三段版本号；
用户端「系统设置」里自动检查有没有被关掉；该版本是不是被用户「跳过」过。

**安装器里的中文变成乱码**
`build.ps1` 和 `installer/MagnetometerSystem.iss` 都必须存成 **UTF-8 带 BOM**。
Windows PowerShell 5.1 没有 BOM 就会按 ANSI 读，中文全乱。用编辑器另存时注意选对编码。
