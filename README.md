# MagnetometerSystem

[English](README.en.md)

当前版本：**[V0.5.0](https://github.com/YIALU/MagnetometerSystem/releases/tag/v0.5.0)** · [变更日志](docs/变更日志.md)。GitHub Release 提供 Windows x64 安装版、便携版与 SHA256 校验文件；应用内自动更新仍使用 Gitee 发布源。

面向日常设备调试的通用磁力仪上位机，使用 **.NET 8 / WPF**。核心工作是：**按用户定义的协议接收数据，连接后自动保存原始读数，并绘制实时曲线**。

通道数量、名称和单位由协议定义；采样率不与设备类型绑定。正交度校正、偏移/增益校准、计算通道等按需使用，不是开始采集的前置条件。

## 从连接到导出

1. **配置连接**：选择串口或 TCP，填写串口参数或地址、端口。
2. **选择或编辑协议**：设置 ASCII 分隔符与字段映射，或二进制帧头、帧段、数据类型、字节序、缩放和校验。确认通道顺序、名称和单位与设备输出一致；协议可以导入、导出 JSON。
3. **填写标称采样率并连接**：标称值用于记录和显示，不会自动改变设备采样频率。改变设备设置需要使用该设备支持的命令。
4. **确认接收与保存**：连接建立前准备采集会话；接收到的有效读数自动进入保存和绘图链路。先检查原始收包与解析结果，再确认保存状态。
5. **观察曲线**：切换单图/多图、显示通道、时间窗口和坐标轴。暂停显示、折叠面板和显示降采样不应影响原始数据保存。
6. **结束采集并导出**：断开连接后等待剩余批次保存完成，在数据管理中选择会话，查看、回放或导出 CSV。

“原始读数”指**协议解析后、校正前的通道数值**，包含协议规定的缩放和单位转换。接收窗口中的原始字节是通信调试回显；当前数据库不是完整线缆字节流的录制文件。

ZDZ_C08 两个预设的 CRC 参数尚未确认，默认会提示并阻止采集；按固件确认的参数配置校验后才能连接。配置步骤、旧协议 JSON 的检查要求及可变长度帧规则见[协议校验与通道单位](docs/协议校验与单位.md)。

设备内部存储下载尚未实现独立接收流程。ZDZ 的“读取存储数据”预设暂不可发送，避免历史帧混入实时会话；数据管理中的 CSV 导出用于本机已保存的会话。普通自定义命令仍由用户负责声明协议含义，不能用自由 HEX 发送来代替尚未实现的隔离下载。

## 工作台功能

| 功能 | 用途 |
| --- | --- |
| 串口 / TCP | 连接设备，查看接收报文和连接状态 |
| 可配置协议 | ASCII 与二进制帧、字段映射、字节序、缩放、校验、JSON 导入导出；特殊协议可使用专用解析器 |
| 自动保存 | 保存会话信息与原始通道读数，查询历史数据、回放、导出 CSV |
| 历史回放 | 按记录时间戳倍速播放、暂停与定位，在历史页面直接查看全部通道；实时连接期间禁用回放 |
| 实时曲线 | 单图叠加、多图单列/双列；单图中的温度与磁场共用时间轴，温度使用独立右轴 |
| 显示与分析 | 通道颜色/顺序/显示偏移、自动坐标、滚动统计、区间分析、显示滤波、总场/梯度/公式计算通道 |
| 面板布局 | 连接、计数、通道、收发和分析区域按需展开；小窗口展开多个区域时可滚动；专注曲线时折叠辅助区域，退出后恢复原有开合和输入 |
| 设备命令 | 协议关联命令组、参数化帧构造、ASCII/HEX 发送及通信日志 |
| 可选校正 | 正交度采集与参数管理、偏移/增益校准、历史数据校正；默认不参与普通采集 |

历史数据批量改正会保存独立版本，标识包含两组配置 ID、通道映射、拟合单位和实际计算参数的指纹。同一配置 ID 修改参数后不会覆盖旧结果；导出改正数据时，从“已保存改正版本”选择，CSV 的 `CorrectionVersion` 列记录完整标识。旧的单配置 ID 记录仍可选择和导出，原始数据不受影响。

正交度参数只能用于相同单位的数据（`uT`、`µT`、`μT` 视为同一单位）；不自动换算偏移参数。旧参数未记录拟合单位，保留为未知，需重新拟合或导入明确单位的参数后才能应用。拟合时实时/历史数据使用已记录单位，CSV 样本必须明确声明单位；默认采集不要求校正参数。

当前正交度**拟合采集/会话导入**仅支持恰好 3 个同单位磁场通道（依次 X/Y/Z）或恰好 6 个（X1/Y1/Z1/X2/Y2/Z2）。尚无任意拟合通道映射选择；含温度、额外通道或元数据不完整的数据源会拒绝直接拟合，避免默取前几个通道。此类数据请先整理为明确三轴列的 CSV 再导入。普通采集、绘图和已有显式通道映射的改正不受此限制。

**发送状态有三个层次**：本地写出完成、收到匹配响应、设备确认执行成功。发送 API 返回成功只证明本地写出；设备是否接受、是否执行，要根据协议响应或实测行为判断。

曲线为每通道保留最近 **100,000 点**，供显示与区间分析；完整会话以 SQLite 中已提交的数据为准。图表不再按 64 通道截断，65 通道场景已有回归测试；更多通道和更高吞吐组合仍需按实际设备与电脑配置测量。

## 运行与开发

- Windows 10/11。
- 源码构建需要 .NET 8 SDK；Visual Studio 开发环境应包含“.NET 桌面开发”工作负载。
- WPF 应用及其界面测试需要 Windows。便携版和安装版由发布脚本生成，可包含 .NET 运行时。

在仓库根目录运行：

```powershell
dotnet restore MagnetometerSystem.sln
dotnet build MagnetometerSystem.sln -c Debug
dotnet run --project src/MagnetometerSystem.App/MagnetometerSystem.App.csproj
dotnet test MagnetometerSystem.sln -c Debug
```

打包说明见 [发布流程](docs/发布流程.md)。版本号源是 [Directory.Build.props](Directory.Build.props)；`AppVersion.cs` 读取构建时注入的版本、提交与构建时间。发布脚本会检查版本标签和工作区状态，不应把开发构建直接视为正式发布包。

## 数据与问题定位

默认数据库：`%LOCALAPPDATA%\MagnetometerSystem\magnetometer.db`。

日志优先保存在程序目录下的 `logs`；目录不可写时回退到 `%LOCALAPPDATA%\MagnetometerSystem\logs`。升级或迁移前应关闭程序并保留数据库副本。旧固定列数据表会保留为 `readings_legacy_*` / `corrected_readings_legacy_*`，对应会话提示需要迁移；当前不会自动转换这些旧数据供回放或导出。

保存失败时立即停止接收新测量并断开，已接受的待写批次保留在进程内，界面显示错误。修复原因后点击“重试保存”，完成旧会话后再重新连接。它不是持久化恢复日志：断电或强制结束进程时，尚未提交的数据仍可能丢失。正常关闭会等待保存完成，保存失败时应处理错误后再退出。

| 现象 | 首先检查 |
| --- | --- |
| 已连接但没有数据 | 设备是否主动输出、串口参数/TCP 地址、设备是否需要启动采样命令 |
| 有原始字节但无有效读数 | ASCII 行尾/分隔符、二进制帧长/字节序/校验范围、字段映射 |
| 曲线数量或数值不对 | 通道索引、单位和缩放；区分原始值、显示偏移与派生值 |
| 曲线在动但保存异常 | 保存错误和待写入状态、数据库目录可写性；曲线更新不代表事务已提交 |
| 命令显示已发送但设备没变化 | 对端实际收到的字节、行尾/校验、响应匹配和设备执行条件 |

报告问题时附上程序版本、复现步骤、连接参数、协议 JSON、最小收发报文及相关日志。明确问题发生在接收、解析、保存、显示、发送或设备执行哪一步，有助于复现。
