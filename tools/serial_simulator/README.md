# 串口数据模拟器

按上位机的协议配置生成数据帧，从虚拟串口的一端发给上位机，用来手动验证接收、解析、保存、绘图和通信诊断。它只模拟设备上行数据，不能代替实体串口和真实设备验收。

## 准备

- Windows，Python 3.9 及以上（自带 tkinter），安装 pyserial：

  ```powershell
  python -m pip install pyserial
  ```

- 一对互连的虚拟串口，例如 ELTIMA 或 com0com 创建的 COM1 ↔ COM2。模拟器用一端，上位机连另一端。

## 启动

双击 `start_simulator.cmd`，或在仓库根目录运行：

```powershell
python tools\serial_simulator\serial_simulator.py
```

## 使用步骤

1. 选择端口（如 COM1）和波特率，点“打开串口”。端口被占用时会提示，请确认上位机连的是配对的另一端。
2. 选择协议。协议说明下方会写出帧长、通道、校验方式，以及上位机应选的端口、波特率和协议。
3. 上位机在连接页选 COM2、相同的波特率和协议，然后连接。
4. 模拟器点“开始发送”。

统计栏的“正常 N 帧”应等于上位机解析通过的帧数，前提是上位机先连接、模拟器后开始发送。统计只计完整写出的帧；写出超时的帧显示为“未发出”。通道表显示最近一帧的物理值，可与上位机的显示对照。对照时注意两点：ASCII 按设置的小数位四舍五入，Float 字段有单精度误差。

## 协议来源

| 来源 | 说明 |
| --- | --- |
| 内置 | `presets/` 下 7 个 JSON，由上位机 v0.5.4 的内置协议（`ProtocolConfig.Create*`）导出 |
| 上位机已保存 | 自动读取 `src/MagnetometerSystem.App/bin/{Debug,Release}/net8.0-windows/Protocols` 和安装目录 `%LOCALAPPDATA%\Programs\MagnetometerSystem\Protocols` |
| 加载 JSON… | 上位机连接页“导出…”得到的协议文件 |

“导出给上位机…”把当前协议保存为 JSON，可在上位机连接页“导入…”，两边使用同一份配置。

CTMBS-3-X2000 是 TCP 端口 81 的请求/推送协议，不在串口模拟范围内。上位机的内置协议改动后，`presets/` 不会自动跟着更新：在上位机导出新的协议，再用“加载 JSON…”打开即可。

### 未启用的校验

数采卡的帧里有 CRC 字段，但固件目前没有计算。上位机的内置协议把这个校验段标为“未启用”，模拟器与之一致：在 CRC 位置填随机字节，上位机照常解析，不比对这两个字节。“坏校验”故障在这种协议下改为破坏帧尾或固定值。

在上位机勾选“启用校验”后，导出协议并在模拟器里用“加载 JSON…”打开，模拟器就会按配置的算法计算校验值。

## 信号

- **磁分量（nT 等）**：按轴给地磁基值，X 约 28000、Y 约 −2500、Z 约 42000 nT。第二个探头（X2 等）再加 35 nT。在基值上叠加所选波形（正弦、方波、三角波、恒定、随机游走），幅值、频率和高斯噪声可调，各轴相位错开。
- **其他通道**：ΔX/ΔY/ΔZ 等于对应两个探头之差；温度（°C）约 25 并缓慢变化；GPS 纬度 30.5、经度 114.3；加速度 Z 约 9.81，陀螺和深度有小幅变化。
- **注入尖峰**：在下一帧的磁分量上加一个大尖峰。

## 故障注入

在上位机的“原始报文”或解析记录里对照下表的预期行为：

| 设置 | 模拟器的行为 | 上位机应有的表现 |
| --- | --- | --- |
| 噪声字节 % | 帧前插入 1–16 个随机字节；文本协议插入一行乱码 | 丢弃未对齐的字节或拒绝该行，后续帧正常 |
| 坏校验 % | 校验值写错。协议没有校验或校验未启用时破坏帧尾或固定值；文本协议把某列写成 `ERR` | 拒绝该帧并重新同步 |
| 截断帧 % | 只发前半帧，紧接着发下一帧 | 拒绝残帧，下一帧正常 |
| 每次写入帧数 | 大于 1 时多帧一次写出（粘包） | 全部解析 |
| 随机分包写入 | 拆成随机小块，间隔 0–2 ms 写出 | 全部解析 |
| 回显收到的数据 | 把上位机发来的字节原样回发 | 用于观察回显型应答 |

解析器只能靠启用的校验、帧尾、参与同步的固定值或长度值发现损坏，截断帧只能靠启用的校验或帧尾发现。协议缺少这些时，对应故障无法被识别，模拟器不注入并在协议说明中注明，避免把会被接收的帧算成坏帧。

单次操作按钮有：发一个坏帧、发一个截断帧、发一段噪声、注入尖峰、发送表头行。“发送表头行”只在 ASCII 协议配置了表头或跳过行时可用。

上位机发来的命令以十六进制和 ASCII 显示在日志里，可以核对命令的实际字节。“复制一帧”把一帧数据放到剪贴板，可以粘贴到上位机连接页的“试解析”：二进制协议为十六进制，文本协议为文本。

## 命令行

```powershell
python tools\serial_simulator\serial_simulator.py --list
python tools\serial_simulator\serial_simulator.py --headless --port COM1 --protocol 7 --rate 200 --seconds 10 --noise 5 --bad 5 --truncate 5 --split
```

`--protocol` 可以是 `--list` 列出的序号、名称片段或 JSON 文件路径。`--seed` 用来固定随机序列，`--batch` 和 `--echo` 的作用与窗口中对应的设置相同。

## 局限

- 设备命令的语义不做实现，只能原样回显。
- 虚拟串口通常不受波特率限制。换成实体串口时，帧率乘以帧长需要低于“波特率 ÷ 10”字节每秒，界面在超出时会提示。
- 用模拟器验证通过只说明虚拟串口链路通过，不等于实体适配器或真实设备通过。
